# @nuxtjs/storybook 为什么拿不到 Storybook MCP 的 docs 工具集

查阅日期：**2026-10-26**（所有 GitHub / 官网内容均于当日抓取）。
范围说明：中途用户把范围收窄为"只看官方有没有表态"。因此本报告分三层，**证据等级不同，请分开看**：

- **【官方表态】**：Storybook 官方文档、Storybook / nuxt-modules 的 issue、PR、release notes 里维护者或官方文字的原话。
- **【源码事实】**：读 npm 发布包与 GitHub 源码得到的事实。它是官方代码，但**不是**官方对"为什么"的解释。
- **【实测】**：在 `/tmp` 里做过的两组最小实验（范围收窄前已完成，收窄后停止，没有继续）。**第三组（手动补 hook）没有做**，相关结论一律标 `[INFERENCE]`。

## 结论（先看这里）

1. **官方没有任何一处解释"为什么" `@nuxtjs/storybook` 不生成 manifest。** Storybook 文档只陈述事实："Vue setups other than `@storybook/vue3-vite`, including `@nuxtjs/storybook`, generate no manifest."（[MCP overview · Framework support](https://storybook.js.org/docs/ai/mcp/overview.md)，v11 文档同句：[overview v11](https://storybook.js.org/docs/11/ai/mcp/overview.md)）。我在 storybookjs/storybook、storybookjs/mcp 里搜 "nuxt manifest / nuxt mcp"，**没有找到任何相关 issue/PR/讨论**；nuxt-modules/storybook 里搜 "manifest"/"mcp" 也没有专门的 issue。
2. **官方对"有没有计划"有表态，但只在 nuxt-modules 一侧，且是"计划、可选、无 ETA"。** 维护者在 [#1093 Next major version](https://github.com/nuxt-modules/storybook/issues/1093)（2026-09-07 开，2026-10-03 关）写了两条："Docgen server support: … The preset will adopt it." 和 "Better MCP support: … the preset will provide its own story-snippet service through OSA."，两条都被放在 **Optional / 可选** 小节，并写明 "**No ETA yet**"。后续 [#1101 Tracker for next major - WIP](https://github.com/nuxt-modules/storybook/issues/1101)（2026-09-19 开，**仍 open**）把"Make the preset fully compatible with SB docgen server"列为目标，目标版本是 **Storybook 11**。Storybook 官方一侧没有 Nuxt 路线图。
3. **直接原因（源码事实，非官方表态）：manifest 的两个 preset hook 只写在 `@storybook/vue3-vite` 的框架 preset 里，而 `@storybook-vue/nuxt` 自己重写了一个 preset，没有把它们导出。** Storybook 启动时只把 `<frameworkName>/preset` 加进 core presets（[build-dev.ts L170-171](https://github.com/storybookjs/storybook/blob/9b4e295a7f994b6496cb1fdd50b436dd64925cca/code/core/src/core-server/build-dev.ts#L170-L171)）。Nuxt 的 preset 只导出 `core`、`previewAnnotations`、`viteFinal`（外加两个工具函数），其中 `viteFinal` 是手动 `import` vue3-vite 的 `preset.js` 并只调用它的 `viteFinal`（[nuxt preset.ts L453-L470](https://github.com/nuxt-modules/storybook/blob/74274ef0d2f1d21b170ead916ed503b960d5a6aa/packages/storybook-addon/src/preset.ts#L453-L470)）。`experimental_manifests` / `experimental_docgenProvider` 因此被丢弃。React 的同名 hook 放在**渲染器**包 `@storybook/react` 的 preset 里（[react preset.ts L29-L33](https://github.com/storybookjs/storybook/blob/9b4e295a7f994b6496cb1fdd50b436dd64925cca/code/renderers/react/src/preset.ts#L29-L33)），所以 `nextjs` 等所有 React 框架都继承得到；Vue 的放在**框架**包里（[vue3-vite preset.ts L16](https://github.com/storybookjs/storybook/blob/9b4e295a7f994b6496cb1fdd50b436dd64925cca/code/frameworks/vue3-vite/src/preset.ts#L16)），任何另起炉灶的 Vue 框架都拿不到。
4. **不是 core 里的框架白名单，也不是 Nuxt 的 Vite 配置不兼容。** core 判断 docs 工具集是否可用只看 feature 开关 + `experimental_manifests` 是否产出（[manifest-status.ts L12-L13, L49-L50](https://github.com/storybookjs/storybook/blob/9b4e295a7f994b6496cb1fdd50b436dd64925cca/code/core/src/cli/skills/manifest-status.ts#L12-L50)），我在 core/addon-mcp 发布包里没有搜到按框架名放行/拒绝 manifest 的代码（搜索范围有限，不能保证没有）。Nuxt 的 `viteFinal` 依然调用了 vue3-vite 的 `viteFinal`（实测日志里能看到 vue-docgen-api 弃用警告，见实测 A）。
5. **版本上不是障碍：`@nuxtjs/storybook` 10.0.3 已经要求 Storybook ≥ 10.6.0**（`peerDependencies.storybook: ^10.6.0`），而 MCP 需要的 `@storybook/addon-mcp` 当前就是 10.6.3。实测里 dev/test 工具集和 `/mcp` 端点都能正常工作。
6. **实测（A）：`@nuxtjs/storybook` + addon-mcp 默认只有 dev 工具集，docs 为 disabled。（B）把 `features.experimentalDocgenServer: true` 加进 main 之后，docs 工具"被列出来"但是空的**：`docs-list` 返回只有标题 `# Components`，`/manifests/components.html` 报 500 `No registered service with id "core/docgen" exists`。即 flag 本身不够，缺的正是 vue3-vite 里那两个 hook。
7. **最可行的路径（按推荐顺序）：**
   - **(a) 如果要 MCP docs 工具集，直接用 `@storybook/vue3-vite`**（官方支持，`componentsManifest` + `experimentalDocgenServer`），代价是自己配 Nuxt 别名 / 自动导入 / Tailwind / i18n 的 Vite 配置，失去 `@nuxtjs/storybook` 的 Nuxt 运行时（NuxtLink、`useRuntimeConfig`、自动导入等）。Storybook 11 会把 docgen server 对有 provider 的框架默认打开（见下文 PR #36401），之后 vue3-vite 不需要再手动设 `experimentalDocgenServer`。
   - **(b) 留在 `@nuxtjs/storybook`，在 `.storybook/main.ts` 里手动补两个 hook** + 两个 feature（`componentsManifest` 由 addon-mcp 自动置 true）。`@storybook/vue3-vite/preset` 在其 `exports` 里是公开子路径。**这条我没有实测（范围收窄前未做）**，属 `[INFERENCE]`，细节和风险见"绕过方案"一节。
   - **(c) 等官方**：nuxt-modules 下一个大版本（目标 Storybook 11）计划做，但被标成可选、无 ETA。
8. **Storybook 官方也承认 Vue 的 manifest 是"带缺口"的**：PR #35924 的描述写 Vue 在 `docs-show` 里 "Not yet"（没有 props 段）；而 10.6 文档表格已经改成 "Yes"。具体 Nuxt 项目里 props 能否出来，需实测。

## 实测（范围收窄前在 `/tmp/nsb-exp` 完成；不在仓库内）

环境：Nuxt 4.6.2（Vite 8.3.5、Vue 3.5.44）、`@nuxtjs/storybook` 10.0.3、`storybook` 10.6.3、`@storybook/addon-mcp` 10.6.3，一个带 JSDoc 的 `MyButton.vue` + 两个 story；`.storybook/main.ts` 使用 `framework: '@storybook-vue/nuxt'`；`nuxt dev` 内嵌启动 Storybook（端口 6106）；用 `curl` 走 `/mcp`（Streamable HTTP JSON-RPC）和 `/manifests/*`。

| 实验          | main.ts 的 `features`                                          | 观察到的结果                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A 基线**    | 不设置（addon-mcp 自动 `componentsManifest: true`）            | `tools/list` = `get-storybook-story-instructions, stories-changed, stories-find-by-component, stories-preview`（**无 docs-\***）；`GET /manifests/components.json` → **404** `Manifest "components" not found`；`/manifests/components.html` → 404 `No components or docs manifest configured.`；`/mcp` 的 HTML 页 docs 为 disabled，提示 "requires a components manifest, which your framework does not generate. On @storybook/vue3-vite, also enable experimentalDocgenServer."；启动日志出现 vue3-vite 的 `vue-docgen-api is deprecated` 警告（证明 Nuxt 的 `viteFinal` 确实走了 vue3-vite 的 `viteFinal`）。 |
| **B 加 flag** | `{ componentsManifest: true, experimentalDocgenServer: true }` | `tools/list` 多出 `docs-list, docs-show, docs-show-story`，HTML 页 docs 变 enabled；但 `docs-list` 返回 `{"content":[{"type":"text","text":"# Components"}]}`（**空列表**）；`/manifests/components.json` → 404 `Manifest "components" is not available in dev when experimentalDocgenServer is enabled`（符合文档）；`/manifests/components.html` → **500** `SB_CORE-COMMON_0007 (OpenServiceMissingServiceError): No registered service with id "core/docgen" exists in this environment.`                                                                                                                      |
| **C 补 hook** | **未做**（范围收窄后停止）                                     | —                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

与源码的对应：B 中 docs 工具被"误报可用"，是因为 `isDocgenServerMode` 只看两个 flag（`manifest-status.ts L49-50`）；`core/docgen` 没注册，是因为 `experimental_docgenProvider` 为空（`common-preset.ts L425-L445`）。这与"hook 在 Nuxt 的 preset 里被丢掉"一致，但**不是**官方对根因的陈述。

## 绕过方案

**方案 1：改用 `@storybook/vue3-vite`（官方支持路径）。** 官方表格明确列出；Storybook 11 后 `docgenServer` 对有 provider 的框架默认开启（PR #36401）。代价是需自己对齐 Nuxt 环境：自动导入（`unplugin-auto-import` / `unplugin-vue-components`）、`@/` 与 `#shared/` 别名、Tailwind v4 的 Vite 插件、`@nuxtjs/i18n` 的 Vue 插件注册。`[INFERENCE]` 这部分正是 `@storybook-vue/nuxt` 做的事，自己维护成本不低；且 #1093 里维护者说 manifest 里的 story snippet 本来也不会反映 Nuxt 自动导入。

**方案 2：在 `@nuxtjs/storybook` 的 main 里手动补 hook。** `@storybook/vue3-vite/preset` 是 `package.json` 的公开 `exports` 子路径（`"./preset": "./dist/preset.js"`，已在 npm 包中确认）。`[INFERENCE]` 思路：

```ts
// .storybook/main.ts（未实测）
import { experimental_docgenProvider, experimental_manifests } from '@storybook/vue3-vite/preset'
export default {
  framework: '@storybook-vue/nuxt',
  features: { experimentalDocgenServer: true }, // componentsManifest 由 addon-mcp 置 true
  experimental_docgenProvider,
  experimental_manifests,
  addons: ['@storybook/addon-mcp'],
}
```

main 文件本身就是一个 preset，导出的同名 hook 会参与 `presets.apply`。需要实测确认的风险：(i) pnpm 下需把 `@storybook/vue3-vite` 加成直接依赖；(ii) docgen 走 `vue-component-meta` + TypeScript Language Service，Nuxt 4 的根 `tsconfig.json` 是 references 形式，Storybook Vue 文档提示这种情况要显式指定 `framework.options.docgen.tsconfig`（[vue3-vite 文档 · Override the default configuration](https://storybook.js.org/docs/get-started/frameworks/vue3-vite.md)），而 `@storybook-vue/nuxt` 的 `framework` 选项类型继承自 vue3-vite（`FrameworkOptionsVue`，见 [types.d.ts](https://github.com/nuxt-modules/storybook/blob/74274ef0d2f1d21b170ead916ed503b960d5a6aa/packages/storybook-addon/src/types.d.ts)）但是否被 `viteFinal`/docgen worker 读取未确认；(iii) 自动导入组件、`#imports`、`@/` 别名下的 props 类型解析质量；(iv) 这是依赖未公开稳定的实验 API（官方说 "the API and format are still experimental and subject to change"，[RFC #35333](https://github.com/storybookjs/storybook/discussions/35333)），次版本升级可能失效。

**方案 3：Storybook composition。** 官方说被组合的 Storybook 若有 manifest，MCP 会自动合并（[MCP overview · Composition](https://storybook.js.org/docs/ai/mcp/overview.md)）。`[INFERENCE]` 可以另起一个 `@storybook/vue3-vite` Storybook 只为产 manifest、再把它作为 `refs` 挂到 Nuxt 的 Storybook；但那等于方案 1 的全部配置成本，外加 manifest 里的组件只在 vue3-vite 那份里能正确渲染。addon-mcp 对缺少 manifest 的 ref 会跳过并告警（"Skipping composed ref … components manifest not found … Enable the `componentsManifest` feature on that Storybook"，见 `@storybook/addon-mcp@10.6.3` 的 `dist/preset.js` L1140）。**不推荐。**

**方案 4：等待官方。** 见结论 2；无 ETA，且可能要换到 Storybook 11。

## 需实测 / 开放问题

1. **方案 2 是否真的出得了 manifest**：补两个 hook 后，`docs-list` 是否列出 `MyButton`？`docs-show` 是否包含 props（Storybook 在 #35924 里写 Vue 当时没有 props 段，10.6 文档表格却写 "Yes"）？
2. 在真实项目（Nuxt 4、`ssr: false`、Tailwind v4 vite 插件、`@nuxtjs/i18n`、`@/` 与 `#shared/` 别名、自动导入）上，`vue-component-meta` 对 `.vue` 组件 props 的解析是否完整；Nuxt 根 tsconfig 是 references 时是否需要 `docgen.tsconfig`。
3. 嵌入模式（`nuxt dev` 内起 Storybook）与独立 `storybook dev` 的 manifest/docs 条目是否一致（见 nuxt-modules [#1074](https://github.com/nuxt-modules/storybook/issues/1074)，open）。
4. `storybook build` 的静态产物里 `manifests/components.json` 是否会生成（dev 下该路由按设计 404）。
5. 手动 hook 在 `@nuxtjs/storybook` 升级（10.0.x → 下一个大版本 / Storybook 11 的 `docgenServer` 改名与 `isDocgenProviderEnabled` 机制）后是否仍然有效。#36401 说 `experimentalDocgenServer` 会重命名为 `docgenServer` 并提供自动迁移，Nuxt 的 preset 不导出 `isDocgenProviderEnabled` 时默认值如何，需在 11 的预发布版上测。
6. 官方是否会把 Nuxt 的 docgen/story-snippet 服务做成 `@storybook-vue/nuxt` 自己的 provider：目前只有 #1093 的一句计划，没有 issue/PR；可在 nuxt-modules 下直接提问并关注 #1101。
7. 本报告 Storybook 侧永久链接固定在 tag `v10.6.3`（commit `9b4e295`），nuxt-modules 侧固定在 tag `v10.0.3`（commit `74274ef`）。`main`/`next` 上的代码可能已变化，尤其是 vue3-vite 的 docgen 默认值（PR #36401）。
