# 对局通过确定性重放从事件日志恢复

对局改在浏览器标签页里运行后，页面关闭或刷新就会暂停对局；我们要求对局能从事件日志恢复到停下处继续，而不是记为终止。引擎的状态本就由事件折叠而来，但控制流（处于哪个阶段、对话轮到谁、剩余发言次数）只存在于 `runGame` 这个 async 过程中，因此恢复时从头重新执行 `runGame`：已在日志里的部分不发请求、不写日志，只核对引擎重新产生的事件与日志一致，选手、说书人与手动裁量直接取日志中被采用的结果，随机数用 `game.created` 里的种子重新生成；日志耗尽后切换为实时运行。

## Considered Options

- **把引擎改写为纯状态机**（控制流位置进入状态，`next(state) → effect`）：恢复最直接，但等于重写整个引擎，被否决。
- **恢复不了就记为终止**：最省事，但浪费已花费的模型调用，也违背“暂停可以继续”的语义，被否决。

## Consequences

- 引擎必须保持确定性：除了经由 ports 的输入外，不得读取时间、`Math.random` 等外部状态。
- 并行批次中的决策写入顺序不确定，重放时按座位与请求匹配，而不是按日志位置。
- 引擎行为或事件形状一旦改变，必须提升 `engineVersion`；版本不符的对局既不能观战也不能继续。版本相同但重放结果与日志不符时，对局以“引擎错误”终止。
