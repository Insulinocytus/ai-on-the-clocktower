# AI on the Clocktower

让多个 LLM 互相对局《血染钟楼》（暗流涌动），供人类观战并比较模型表现的自部署、单用户 web app。术语见 [`GLOSSARY.md`](GLOSSARY.md)，整体规格见 [#16](https://github.com/Insulinocytus/ai-on-the-clocktower/issues/16)。

技术栈：Nuxt 4（Nitro 常驻进程）· SQLite（better-sqlite3，WAL）· shadcn-vue（Tailwind v4 + Reka UI）· `@nuxtjs/i18n` · Vitest。

界面由浏览器渲染（`ssr: false`），Nitro 常驻进程提供 API；目前不涉及 shadcn-vue 的 SSR hydration。

## 快速开始

需要 [mise](https://mise.jdx.dev/)：仓库根的 `mise.toml` 固定 Node 与 pnpm 版本。

```sh
mise install
pnpm install
cp .env.example .env   # 填入各提供商的 API key
pnpm dev               # http://127.0.0.1:3000
```

生产运行：

```sh
pnpm build
pnpm start             # 读取 .env，默认只监听 127.0.0.1:3000
```

可用环境变量见 [`.env.example`](.env.example)。数据库默认在 `.data/app.db`。

## 模型管理

在“模型”页录入：

- **LLM 提供商**：名称、OpenAI 兼容的 base URL、凭据环境变量名、单次调用超时（默认 300 秒）、最大并发（默认 5）。API key 只放在 `.env` 或进程环境里；数据库只存变量名，界面和接口只显示它是否已设置。
- **模型预设**：名称、所属提供商、模型名、是否允许强制 `tool_choice`、`extra_body`（JSON 对象，原样合并进每次请求，例如 `{"max_tokens": 4096}`）。
- **试调用**：用整局固定的六个工具和最小提示请求 `speak`，只将参数符合 schema 的单个 `speak` 调用判为合法，并展示原始响应；结果不存档。关闭弹窗会取消浏览器等待，迟到结果不会覆盖其他预设的试调用；已发送的上游请求仍可能执行到结束或提供商超时。

`extra_body` 不能覆盖 `temperature` 的禁用策略；预设不允许强制工具时，其中的 `tool_choice` 也不会下发。服务端诊断和提供商原始响应保留原文，界面控件支持中英切换。

## 对局与观战

在“对局”页新建对局，选择 5–15 个座位并分别选择模型预设（可以重复），再选择对局语言、每人每段对话的发言上限（默认 10，至少 1）与每人每个私聊阶段的房间数（默认 3，至少 0；0 跳过私聊）。以已有对局为模板时保留人数与各座位预设；改变人数保留前面的座位，新加座位须另选预设。缺少所用提供商凭据时，开局会被拒绝并列出环境变量名。种子由服务端生成，模型预设快照和流程参数写入日志，之后修改预设不会改变旧对局。

当前角色池包括暗流涌动全部 22 个角色，支持规则配置表中全部 5–15 人配置，裁量按所配置来源执行。男爵在场时必须将两名镇民替换为两名外来者；酒鬼占外来者名额，另从不在场的镇民中选择其以为的角色。配置校验与抽样都排除“唯一镇民是洗衣妇”的开局，返回 `no_washerwoman_truth`：这是对规格 D1 校验清单的明确补充，因为 D4 的两名对象必须排除接收者，否则该配置没有合法真信息。7 人及以上在首夜前用 D7 选定三个不在场的善良角色作为恶魔伪装，首夜爪牙得知恶魔与其他爪牙，恶魔得知全部爪牙及伪装；5–6 人不提供这些信息。小恶魔夜里自杀成功时，死亡前至少五人存活且红唇女郎存活、能力有效，则必须由她继位；否则用 D14 从存活的真爪牙中选择，没有继位者则善良获胜。夜里继位者当夜不再行动，变身不额外告知同伴。首夜分配角色并结算信息；黎明公告后进行公聊，死亡座位照常参加；其他夜晚由小恶魔选择目标，直到一方获胜。公聊同时询问所有非上一位发言者且仍有条数的座位，从非 pass 中优先采用剩余条数最多者的一句，平局用种子随机；落选发言只留在决策日志里。所有可接话者 pass 或无人可接话则结束公聊。任何座位都可在非空公聊发言上声称猎手开枪；假开枪公开结算为“无事发生”。选手时间线只在换天时删除早于前一天的公聊和私聊发言，不添加省略标记，其他事件始终保留。没有天数上限；反复选择士兵或死者且无人处决时，对局可能一直继续。

随机 D1 先在该人数全部合法角色集合中等概率抽取一组（含男爵修正及洗衣妇限制），再等概率分配座位，不先等概率挑选爪牙。酒鬼以为的角色另由 D2 从未在场镇民中选择。同一种算法下固定种子可复现；本次修正改变了旧算法中相同种子的开局结果，已保存的事件日志不受影响。

黎明后、公聊前的私聊阶段按轮推进：有剩余次数的座位提议房间（自动加入自己），相同成员构成合并；各座位只看到包含自己的匿名候选房间与稳定编号。未获全员排入的房间删除，其余按全体成员排名之和从小到大分配，平局用种子随机，成员已被分走的房间整体落选，不缩小房间。成立的房间并行使用同一套对话机制；成员名单公开，内容和关闭事件仅成员、说书人与观战者可见，私聊不能开枪。只有进入成立的房间才扣次数；所有人次数用完或一轮没有房间成立则进入公聊。死亡座位照常私聊。

公聊结束后进入提名阶段：存活者同时提名或 pass，多人提名时按种子随机受理一个，依次说明理由、辩护、顺时针投票；达到门槛且独占最高票者在提名结束时被处决，平票不处决。死者只有一枚投票标记，用完后不再为投票调用模型。处决小恶魔时满足条件的红唇女郎立即继位，下一夜可以行动；随后入夜。

洗衣妇、图书管理员和调查员的首夜信息按所配置来源从显式枚举的合法候选中选择，随机来源均匀抽取，两名玩家均不包括接收者；没有可被探测为外来者的座位时，图书管理员直接得到“0”。占卜师在首夜前固定一名善良干扰项（可以是自己），每夜选择两名不同玩家并得知“是/否”，死恶魔仍判“是”。送葬者只在前一天有人实际死于处决后得到该死者的角色；再次处决死者不提供信息。守鸦人夜里死亡后当场选择一名玩家并得知其角色，可选自己或死者，白天死亡不触发。开局在 D2、D3 后按 D10、D11 顺序固定间谍、陌客被当作的阵营与角色，两字段独立选择并写入魔典；能力无效期间返回真实身份，恢复后仍使用原结果，死亡不取消被当作。仅规则 §6.2 的十种探测使用这些结果，包括贞洁者 D16 与猎手 D17；继位、恶魔死亡和胜负始终使用真实身份。间谍每个存活夜晚直接得到真实魔典（含状态、酒鬼身份、被当作结果和占卜师干扰项），即使中毒也不走 D8。圣徒仅在能力有效且死于处决时令邪恶立即获胜；夜间死亡、死者再处决和中毒处决不触发，双方同时满足胜利条件仍善良优先。男爵死亡或能力无效不撤销开局的人数修正。

同一提供商的请求跨局共享进程级 FIFO 队列（试调用也使用同一上限），每次发放槽位时读取当前最大并发。排队不计入调用超时，也不额外消耗尝试次数；每次重试重新排队，退避等待期间不占槽位。

僧侣、镇长、贞洁者和猎手已加入五人角色池。僧侣首夜不行动，之后每夜保护一名非自己玩家，防止小恶魔击杀（包括小恶魔自杀）；保护不阻止处决或猎手。镇长遇袭且未受保护时，随机裁量 D12 先等概率决定是否替死，再由 D13 均匀选另一座位；死者、有效士兵或受保护者替死时无人死亡。白天结束时恰好三人存活、无处决且镇长能力有效，善良获胜。

贞洁者第一次被有效提名就消耗能力；有效贞洁者被当作镇民的玩家提名时，提名者立即处决并结束白天，覆盖原处决候选。真正猎手首次公聊开枪可杀死被当作恶魔的玩家并照常处理真实恶魔继位；打空或能力无效也消耗次数，死者或假猎手开枪一律无事发生。管家每夜选择非自己的主人（可为死者或重复目标），投票请求写明主人及跟票限制，但违规票照计；死者管家不受限制。

投毒者每夜首先选择一名玩家中毒，包括自己或死者；中毒持续至次日黄昏，投毒者死亡或变成小恶魔时立即解除，自毒不会立即解除。全部能力共用“不是酒鬼且未中毒”的有效性判定；无效能力照常选择但不产生效果，每局一次的使用仍消耗。醉酒或中毒的信息改走 D8（间谍魔典例外），按能力的输出形式显式枚举，允许真信息；事件分别记录真实结果、实际告知、是否偏离和原因，不向座位透露状态。酒鬼的真实角色仍是外来者，用 D2 选择未在场镇民作为告知身份并按该角色唤醒；酒鬼占卜师不设置干扰项。

D8 的调查员告知始终为一张爪牙角色牌加两名其他玩家，不会只给“0”；图书管理员仍可得到“0”。

对局列表的状态由事件日志推出。打开运行中的对局进入直播，结束或终止的对局进入回放。桌面宽屏观战页采用三栏：左侧按事件切分频道块，中间座位环显示所选块最后一条事件时的魔典，右侧显示该块内容。夜晚、黎明、公聊、提名和每个私聊房间分别成块；私聊分配块默认隐藏，同一天相同成员再次私聊会标注轮次，房间成立公告位于该房间块开头。上帝视角默认显示真实角色与状态；切换说书人、某个座位或仅公开信息时，事件通过 API 的既有受众投影获取，座位环使用相同投影折叠，夜间死亡在公开视角下到黎明才出现。任何视角都显示模型预设名、即将被处决者、存活人数和过半门槛。

直播自动跟随最近收到事件的频道块，点击旧块停止跟随，点“● 回到直播”恢复；回放使用“上一块 / 下一块”或直接点击导航，不提供播放、倍速或时间轴。终止和模板按钮位于观战顶栏，界面语言在应用顶栏切换；模板文案和角色名跟随界面语言，AI 原话和内心推理不翻译。“内心推理”开关控制行动下方默认折叠的理由与原始响应；选手理由只在上帝视角可见，说书人理由按说书人受众显示。“落选决策”默认关闭，开启后落选发言、pass、落选提名及私聊分配块变淡显示，包括未成立任何房间的轮次。点击座位查看按块分隔的足迹，只包含它自己的行动和指向它的事件，不含同房间他人发言，也不超出当前所选块的事件边界；切换频道块返回普通内容。上帝视角根据能力真值结算为对应告知标注“此信息为假”，其他视角不显示该标记。直播先订阅 SSE 再补齐历史，重连按 `Last-Event-ID` 续传并按 seq 去重。日志版本不兼容时禁止回放。

观战页的“终止对局”按钮在运行中（包括等待手动裁量时）可用；`POST /api/games/:id/abort` 返回更新后的摘要，重复终止或对已结束的对局调用不改变日志。人类终止会取消本局所有在途和排队调用，被取消的调用不写决策事件；正常获胜也会取消尚未完成的调用，但不会补写终止事件。

14 项裁量（D1、分座、D2–D8、D10–D14）默认全部手动，可逐项设置或一键全部改为随机、说书人模型、手动；只有用到说书人模型时才需要指定其预设。轮到手动裁量时，运行器在内存中无限期等待，列表显示“等待手动裁量”。观战弹窗显示请求发生时的魔典（含模型预设）、真值、官方建议与合法候选；收起后可用顶栏 ⚠ 恢复，也可直接终止对局。D1 与分座同源时合并一次按座位选角色；异源时先选角色集合，再按指定来源分座。手动配置表单共用规则校验，实时检查重复角色、人数与男爵修正、`no_washerwoman_truth`，可“随机填一份”。

`POST /api/games/:id/discretions/:seq` 接受 `{ choice }`，`seq` 是手动请求事件序号。只有首个合法提交生效，不写理由或模型决策；非法、重复、过期以及终止后的提交都返回 409。重复提交的响应 `data.choice` 给出已采用的服务器结果，界面提示“已在别处提交为 X，按服务器结果继续”。挂起不跨进程恢复：重启后仍按既有规则终止未完成的对局。

候选按结构比较：对象字段顺序不影响手动提交是否合法，数组顺序仍有意义。

每次进程启动会为日志中尚无 `game.ended` 或 `game.aborted` 的对局补写“进程重启”终止事件，不恢复对局；已结束或已终止的对局保持不变。

提名阶段使用日志格式版本 2（决策请求显式记录工具类型），提示词版本 3；旧版本日志不转换，仍保留在数据库，但不能回放。

对局列表和观战页可选“以此局为模板新建”：表单复制原局配置，模型预设按当前 id 选择，种子重新生成。已经删除的预设会在对应座位（或说书人）标红，必须重新选择才能开局；已修改的预设使用当前设置，不改动原局日志。日志版本不兼容的对局不能作为模板。

提供商与模型预设 id 使用 SQLite `AUTOINCREMENT`，删除后不复用；首次启动旧库时按 `PRAGMA user_version` 迁移并保留现有数据。迁移前已经复用的旧 id 无法追溯恢复。

每次决策每轮最多尝试 5 次，输出不合法与调用失败共用次数。不合法输出会立即重试，仅在请求末尾追加原始工具名、参数和对局语言的错误说明；参数违反 schema 时逐条附上字段路径、实际值和允许值。失败尝试不产生游戏效果，也不更新备忘录。调用失败按 `Retry-After`（秒数或 HTTP 日期）等待；无有效值时按 250 毫秒起倍增退避（每轮重新从 250 毫秒开始），原样重发。每次尝试分别记入决策事件。第 5 次仍失败时写入 `game.paused`（座位或裁量、最后一次错误）并暂停对局，等观战者在对局页选择“重试”（`POST /api/games/:id/resume`，写入 `game.resumed`，同一次暂停中所有失败的决策各再给 5 次，次数和已追加的错误说明继续累积）或“终止”（原因记为观战者终止）。暂停期间重启进程同样补写“进程重启”终止。模型预设的试调用仍只发一次请求。

每个座位的备忘录最多 2000 字；所有工具的可选 `memo` 字段省略时保持不变，提供时整份替换（空字符串清空）。只有通过校验的决策会更新备忘录，pass 和落选决策同样有效。更新写成座位私有事件，说书人与观战者也可见，其他座位不可见；不进入选手时间线，后续请求只带最新一份。需要跨天保留的判断、计划、对外说法和关键原话应写进备忘录。

实现地图：

- `shared/types/game.ts`：事件、配置、魔典和 `Ports` 的共享契约。
- `shared/game/roles.ts`：22 个角色的官方双语名称、能力、夜序与提示标记。
- `shared/game/rules.ts`：纯 TS 规则脚本、种子随机数、配置校验、两个折叠与受众投影。
- `shared/event-templates.ts`：双语、按观察者人称渲染的事件模板。
- `shared/prompts/`：版本化双语规则块与无状态选手提示词。
- `server/utils/llm.ts`：OpenAI 兼容 Chat Completions 传输；`tools.ts`：固定工具与 schema 校验。
- `server/utils/game-runtime.ts`：每局异步任务、逐次决策日志、有限重试、三来源裁量分派、等待手动裁量与失败暂停。
- `server/utils/game-store.ts`：SQLite 只追加日志、日志状态与 SSE 订阅。
- `server/api/games/`：开局、列表、详情、投影事件、可续传 SSE、终止与暂停后重试。
- `app/pages/games/` 与 `app/components/Spectator*.vue`：新建对局、列表、三栏直播与回放；`shared/game/channels.ts` 按事件切分频道块，`shared/game/spectator.ts` 关联可见决策理由、假信息与有边界的座位足迹。

HTTP：`POST /api/games` 接受 `{ presets: [id, id, id, id, id], language: "zh" | "en", speechLimit?: number, whisperLimit?: number }`（`speechLimit` 为至少 1 的整数，默认 10；`whisperLimit` 为至少 0 的整数，默认 3）；`GET /api/games` 与 `GET /api/games/:id` 返回日志派生摘要；`GET /api/games/:id/events?after=seq&observer=spectator` 返回事件；`GET /api/games/:id/stream` 为 SSE，参数相同，另支持 `Last-Event-ID`。观察者为 `spectator`、`storyteller`、`seat:1`–`seat:5` 或 `public`。

开局配置还接受 `discretions?: Partial<Record<DiscretionId, "random" | "storyteller" | "manual">>` 与 `storyteller?: presetId | null`，逐项保存到 `game.created`。只有使用说书人模型来源时才要求其预设，并一并检查提供商凭据；否则保存为 null。D1 与分座来源相同时合并决定，来源不同时先选角色集合、再排列到座位。合法候选只有一个时不写裁量事件，也不调用外部来源。

说书人模型使用整局固定的 `decide` 工具（必填 `reasoning`，可选 `seats`、`roles`、`number`、`answer`、`alignment`）。提示词按“共用完整规则 + 说书人原则 → 说书人时间线 → 各座位最新备忘录 → 当前真实魔典与本次裁量”排列，中英随对局语言；合法范围用结构描述，不堆砌候选组合。官方建议仅放在对应请求，不缩小硬约束候选。时间线保留整局全部实际公聊、私聊、夜间行动及此前说书人决定与理由，不使用选手的两天发言窗口，也不包含选手推理、落选发言、私聊原始提议或排序。输出按裁量编号匹配引擎合法候选，选角与分座使用配置校验；重试、提供商 FIFO 队列、取消与选手调用共用。每次尝试记录 `storyteller.decision`，成功结算关联其 seq；说书人以下视角看不到这些事件。

> [!WARNING]
> 本应用没有任何鉴权，默认只监听 `127.0.0.1`。如需暴露到外网，请自行在反向代理上加鉴权，再放宽 `HOST`。

## 开发

```sh
pnpm check   # prettier --check → nuxt typecheck → eslint → knip → vitest
pnpm format  # prettier --write
```

`pnpm install` 会通过 `simple-git-hooks` 安装 pre-commit hook，提交前自动跑 `pnpm check`；pull request 上 GitHub Actions 同样跑 `pnpm check`。

测试缝为规则和应用两处：`test/rules.test.ts` 用脚本化 `Ports` 驱动 `runGame` 并核对事件、折叠和逐格受众；应用测试用 `@nuxt/test-utils` 构建并启动整个应用，经 HTTP API 驱动。`test/fake-provider.ts` 是按脚本返回 tool call、非法输出、429 + Retry-After、5xx 或超时的本地假 OpenAI 兼容提供商；`test/games.test.ts` 包含整局烟雾测试。界面不写自动化测试。

私聊应用测试按本次请求的目标数量回答夜间选择，不依赖随机分配的角色池；中英请求均保留私聊重试、房间分配与投影隔离断言。
